\# GramByte Technologies Frontend Design Skill



\## Project



This project is the official website for GramByte Technologies Inc.



This is a rebuild and major visual upgrade of an existing GramByte website.



Do not treat this as a generic startup landing page.



The existing website establishes the company's content, identity, services, founder presence, interactions, and overall direction.



The new website should preserve that identity while rebuilding the experience with:



\- Next.js App Router

\- TypeScript

\- Tailwind CSS

\- Motion for React

\- Reusable React components

\- Modern responsive design

\- Strong accessibility

\- Strong performance

\- Refined interactive experiences



The finished website should feel custom-built for GramByte Technologies.

\## Motion System



Use Motion for React.



Import from:



motion/react



Motion should communicate hierarchy and responsiveness.



Preferred techniques:



\- Scroll-triggered reveals

\- Staggered content

\- Text reveals

\- Image reveals

\- Subtle parallax

\- Controlled 3D movement

\- Hover responses

\- Section transitions

\- Navigation transitions

\- Interactive project transitions



Typical duration:



200ms to 700ms



Longer sequences may be used only when they clearly support storytelling.



Avoid:



\- Constant bouncing

\- Excessive floating objects

\- Animating everything

\- Slow entrance animations

\- Motion that blocks interaction

\- Animation purely for decoration



Respect:



prefers-reduced-motion



The site must remain fully usable when motion is reduced.

\- Motion

\- Scroll progress

\- Pointer interaction

\## Accessibility



Use semantic HTML.



Maintain correct heading hierarchy.



Provide meaningful alt text.



Decorative imagery should use appropriate empty alt attributes.



Support keyboard navigation.



Use visible focus indicators.



Maintain sufficient contrast.



Do not communicate information through color alone.



Respect reduced-motion preferences.



Interactive custom elements must expose appropriate accessible states.



\---



\## Performance



Performance is part of the design.



Target Lighthouse scores of 90 or higher where practical for:



\- Performance

\- Accessibility

\- Best Practices

\- SEO



Prefer:



\- Server Components

\- next/image

\- next/font

\- Lazy loading

\- Code splitting

\- Optimized assets

\- Minimal client-side JavaScript



Only add "use client" where required.



Do not make the entire page a Client Component simply because some sections contain animations.



\---



\## React Architecture



Use Server Components by default.



Create Client Components only for functionality requiring:



\- Motion

\- State

\- Browser APIs

\- Pointer interaction

\- Scroll interaction

\- Event handlers



Keep interactive boundaries focused.



Avoid unnecessary global state.



\---



\## Tailwind



Use Tailwind CSS for the primary styling system.



Create reusable design tokens.



Keep class structures readable.



Extract repeated UI patterns into components.



Do not create enormous unreadable class strings when a component or reusable pattern would be clearer.

\## Creative Standard



For every major section ask:



Does this look specifically designed for GramByte?



Does the section have a clear hierarchy?



Does the interaction improve understanding?



Does the animation serve a purpose?



Does it work without animation?



Does it work on mobile?



Does it remain accessible?



Does it feel connected to the rest of the website?



If the answer is no, refine the section.
